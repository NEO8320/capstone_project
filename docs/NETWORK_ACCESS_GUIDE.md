# 시연 네트워크 접속 가이드 (WiFi·도메인 없이 폰으로 접속)

> 상황: 시연 데스크탑은 **랜선**으로 연결돼 있고, 발표장 공용 WiFi에 의존하고 싶지 않다.
> 도메인·클라우드 배포 없이, 청중이 자기 폰으로 우리 서비스에 접속하게 하려면?
>
> 핵심 답: **데스크탑을 그대로 두고, 폰을 "데스크탑과 같은 네트워크"에 올리면 된다.**
> 우리 서비스는 노트북/데스크탑 안(localhost)에서 돌고, 같은 네트워크의 폰이 그 IP로 접속한다.
> 이건 인터넷 공개가 아니라 **폐쇄 로컬 네트워크**라 도메인·저작권·보안 노출이 없다.

---

## 방법 A — 데스크탑을 핫스팟으로 (가장 확실, WiFi 불필요) ★추천

랜선으로 인터넷에 연결된 데스크탑이 **스스로 WiFi를 쏘게** 만들어, 폰을 거기에 붙인다.
발표장 공용 WiFi가 전혀 필요 없다.

### 준비물
- 데스크탑에 **WiFi 어댑터**가 있어야 한다(내장 WiFi 또는 USB 무선랜 동글, 수천 원).
  랜선만 있고 WiFi 모듈이 없으면 USB 무선랜 하나만 꽂으면 된다.

### 설정 (Windows 11 기준)
1. 설정 → 네트워크 및 인터넷 → **모바일 핫스팟** 켜기
2. "다음에서 인터넷 연결 공유": **이더넷(랜선)** 선택
3. 네트워크 이름(SSID)·비밀번호 확인(편집 가능)
4. 폰 WiFi에서 그 SSID에 접속

### 접속
1. 데스크탑에서 핫스팟 IP 확인 (PowerShell):
   ```powershell
   ipconfig
   ```
   → "모바일 핫스팟" 또는 "로컬 영역 연결* " 어댑터의 IPv4 (보통 `192.168.137.1`)
2. 폰 브라우저에 `http://192.168.137.1:5173` 입력
3. 끝. 폰은 데스크탑이 만든 핫스팟에 붙어 있으므로 항상 같은 네트워크다.

> 핫스팟은 동시 접속이 보통 8대 정도로 제한된다. 청중이 많으면 방법 B(공유기) 권장.

---

## 방법 B — 데스크탑이 물린 공유기의 WiFi 사용

발표장 데스크탑의 랜선이 어떤 **공유기/스위치**에 꽂혀 있고, 그 공유기에 WiFi도 있다면,
폰을 그 공유기 WiFi에 연결하면 데스크탑과 같은 LAN이 되어 IP로 접속된다.

1. 데스크탑에서 `ipconfig` → "이더넷" 어댑터의 IPv4 확인 (예: `192.168.0.20`)
2. 폰을 같은 공유기 WiFi에 연결
3. 폰 브라우저에 `http://192.168.0.20:5173`

> 학교·공용 공유기는 보안상 기기 간 통신을 막는 "AP 격리"가 켜져 있을 수 있다.
> 이러면 폰↔데스크탑 접속이 안 된다 → **방법 A(데스크탑 핫스팟)로 우회**.

---

## 공통 필수 체크 — Windows 방화벽 허용

같은 네트워크여도 데스크탑 방화벽이 외부 접속을 막으면 폰에서 안 열린다.
프론트(5173)·백엔드(8000) 인바운드를 한 번만 허용한다(관리자 PowerShell):

```powershell
netsh advfirewall firewall add rule name="NewsCurator-5173" dir=in action=allow protocol=TCP localport=5173
netsh advfirewall firewall add rule name="NewsCurator-8000" dir=in action=allow protocol=TCP localport=8000
```

> 프론트(Vite)는 `--host`로 떠 있어 외부 접속을 허용한다. 백엔드는 프론트의 프록시를 통해
> 호출되므로, 폰에서 보이는 주소는 `:5173` 하나면 충분하다(8000은 데스크탑 내부에서 프록시).

---

## 청중 접속 편의 — QR 코드

청중이 IP를 손으로 치면 번거롭다. 접속 주소를 **QR 코드**로 만들어 발표 화면/슬라이드에 띄운다.
- 네이버 'QR 코드' 검색 또는 임의 QR 생성기에 `http://<데스크탑IP>:5173` 입력 → 이미지 저장
- 청중은 폰 카메라로 스캔 → 바로 접속

---

## 발표 전 리허설 체크리스트

1. 데스크탑에서 `.\run_all.bat` 실행 → 백엔드(:8000)·프론트(:5173) 둘 다 떴는지 확인
2. 데스크탑 자신의 브라우저에서 `http://localhost:5173` 정상 동작 확인
3. 방법 A(핫스팟) 또는 B(공유기) 설정 + 방화벽 규칙 추가
4. `ipconfig`로 접속 IP 확인 → **본인 폰으로 먼저 접속 테스트**
   - 피드가 뜨면 성공. 청중도 됨.
   - 로딩만 되고 안 뜨면 → 방화벽(위 명령) 또는 AP 격리(→ 방법 A로 전환)
5. QR 코드 만들어 슬라이드에 삽입
6. (대비) 게스트 모드 버튼으로 가입 없이 바로 체험 가능함을 안내

## 자주 묻는 트러블슈팅

| 증상 | 원인 | 해결 |
|------|------|------|
| 폰에서 계속 로딩만 됨 | 방화벽 차단 | 위 netsh 명령으로 5173/8000 허용 |
| 같은 WiFi인데 접속 불가 | 공유기 AP 격리 | 방법 A(데스크탑 핫스팟)로 우회 |
| `Blocked request. This host is not allowed` | Vite host 제한 | `frontend/vite.config.js`의 `server`에 `host: true` 확인(이미 --host로 기동) |
| IP가 매번 바뀜 | DHCP 동적 할당 | 시연 직전 `ipconfig`로 재확인(핫스팟은 192.168.137.1로 대체로 고정) |
| 청중 많아 일부 접속 안 됨 | 핫스팟 동시접속 한계(~8대) | 공유기 WiFi(방법 B) 사용 |

> 요약: **방법 A(데스크탑 핫스팟) + 방화벽 허용 + QR 코드**가 발표장 WiFi·도메인 없이
> 폰 접속을 보장하는 가장 확실한 조합이다.
