## 1. Windows 한글 깨짐 근본 해결 (PowerShell shim 아키텍처)

- **문제**: 한국어 Windows에서 `setup.bat`·`run_all.bat` 실행 시 한글이 깨지고
  `'enAI'은(는) 내부 또는 외부 명령…` 같은 명령 미인식 오류가 쏟아짐. 수동으로
  `$env:PYTHONIOENCODING="utf-8"`을 설정해야만 백엔드가 겨우 떴음.
- **원인**: 한국어 Windows의 `cmd.exe`는 `.bat` 파일을 **cp949로 미리 버퍼링**한 뒤 파싱한다.
  파일이 UTF-8이어도 `chcp 65001`이 적용되기 전에 한글 바이트가 깨진 명령으로 해석됨.
  → 순수 `.bat`로는 회피 불가능한 Windows 고질 문제.
- **해결**: **3겹 방어 + 아키텍처 전환**
  1. `.bat`는 **ASCII 전용 얇은 shim**으로 축소 (모든 바이트가 코드페이지 중립).
  2. 실제 로직·한글 출력은 **PowerShell `.ps1`**(UTF-8 BOM)로 분리.
     `setup.bat → scripts/setup.ps1`, `run_all.bat → scripts/run_all.ps1`.
  3. 자식 cmd 창(백엔드/프론트)도 `chcp 65001`로 UTF-8 시작.
  - 추가 버그: cmd `/k` 안에서 `set PYTHONUTF8=1`을 인라인으로 넣으면 값 끝에 공백이 붙어
    `Fatal Python error: invalid PYTHONUTF8` 로 죽던 문제 → 환경변수는 PowerShell 부모에서
    상속하도록 인라인 set 제거.
- **결과**: 수동 환경변수 없이 `.\run_all.bat` 더블클릭/실행 모두 한글 정상. 조원·타 PC에서
  바로 실행 가능.
- **관련 파일**: `setup.bat`, `run_all.bat`, `scripts/setup.ps1`, `scripts/run_all.ps1`,
  `start_backend.py`, `backend/app/main.py`

## 2. 백엔드 `.env` 로드 실패 수정 (NAVER 키 미인식)

- **문제**: `backend/.env`에 NAVER API 키를 정확히 넣었는데도 *"NAVER_CLIENT_ID/SECRET
  미설정 — 크롤링 불가"* 가 뜨며 실제 크롤링이 거부됨.
- **원인**: `pydantic-settings`가 `.env`를 **현재 작업 디렉터리(cwd) 상대경로**로 찾는데,
  `start_backend.py`가 cwd를 프로젝트 루트로 바꿔서 `backend/.env`를 못 찾음 → 모든 설정이
  기본값(빈 문자열)으로 폴백.
- **해결**: `config.py`에서 `.env`를 **모듈 자기 위치 기준 절대경로**(`_ENV_FILE`)로 로드 →
  실행 위치와 무관하게 항상 `backend/.env`를 읽음.
- **결과**: NAVER 키·SECRET_KEY 정상 로드 확인, 실제 뉴스 크롤링 작동.
- **관련 파일**: `backend/app/core/config.py`

## 3. 부족 우선 크롤링 배분 (카테고리 균형)

- **문제**: 카테고리별 기사 수가 크게 불균형(정치 편중).
- **해결**: `pipeline.py`에 `_get_category_counts()`(카테고리별 DB 기사 수 조회) +
  `_allocate_crawl_budget()`(부족한 카테고리에 수집 예산 더 배분). 공식은
  `weight = (max_count − count) + 1` 비례 배분이며, 부족한 카테고리부터 수집한다.
- **부가 버그 수정**: 처음 `Article.id`로 카운트하다 PK가 `url`이라 오류 발생 →
  `func.count()`로 수정.
- **결과**: 시간이 지날수록 카테고리 분포가 자동으로 균형을 맞춤.
- **관련 파일**: `backend/app/services/pipeline.py`

## 4. 카테고리 오분류 수정 (정치 기사가 생활·문화에 섞임)

- **문제**: 시연 중 정치 기사가 '생활·문화' 탭에 박히는 현상.
- **원인**: 빈 탭 문제를 고치며 IT·과학·생활·문화를 **sticky 카테고리**(크롤러 분류를
  GPT보다 우선)에 넣었는데, 두 카테고리의 검색 키워드("문화", "IT")가 너무 넓어
  정치/경제/사회 기사가 대량 딸려옴. GPT는 이를 정확히 분류하는데 sticky가 그 정확한 분류를
  무시하고 전부 생활·문화/IT·과학으로 욱여넣음.
- **해결**: sticky를 **세계/연예/스포츠 3개로 축소**(키워드가 명확한 것만). IT·과학·생활·문화는
  GPT의 정확한 분류를 신뢰. 빈 탭 문제는 이미 서버사이드 카테고리 필터링으로 해결됨.
- **결과**: 정치 기사는 정치 탭, 생활 기사만 생활 탭으로 정상 분류.
- **관련 파일**: `backend/app/services/pipeline.py` (`STICKY_CRAWLER_CATEGORIES`)

## 8. AI 요약 깨짐 수정 (`\n` 글자·영어 머리말)

- **문제**: 일부 기사의 'AI 3줄 요약'에 `\n`이 글자 그대로 보이고, "Here is a 3-line
  summary of the article:" 같은 **영어 머리말**이 섞여 출력됨.
- **원인**: 요약 프롬프트의 *"각 줄은 줄바꿈(`\n`)으로 구분합니다"* 지시가 Llama로 하여금
  **리터럴 `\n` 문자**를 출력하게 만들고, 후처리는 `요약:`/`Summary:`만 제거해 영어 안내문을
  못 걸렀음.
- **해결**: 프롬프트에서 `\n` 지시 제거 + `_clean_summary()` 함수 신설 — 리터럴 `\n`을 실제
  줄바꿈으로 변환, 영어/한국어 머리말 제거, 완전 영어 응답이면 `None` 반환해 description으로 폴백.
- **결과**: 새 크롤링 요약이 깔끔한 한국어 3줄로 표시.
- **관련 파일**: `backend/app/services/llm_processor.py`

## 9. 기자명 추출 개선 + 기자 구독 버튼 항상 표시

- **문제**: 외부 언론사 기사에서 **기자 구독 버튼이 아예 안 보임**.
- **원인**: 기자명 추출이 "본문 끝 200자 + `홍길동 기자` 패턴"만 보던 탓에 외부 언론사에서
  자주 실패. 프론트는 기자명이 없으면 버튼을 숨기도록 되어 있었음.
- **해결**:
  - 백엔드: `_extract_journalist()`를 **다단계 추출**(본문 끝/앞 + 이메일 근접 + 역순 어순 +
    description 보조)로 개선, '기자회견·기자단' 등 오매칭은 차단.
  - 프론트: 기자명이 없어도 버튼이 사라지지 않고 **"기자 정보 없음" 비활성 버튼**으로 표시.
- **결과**: 기자 추출률 상승 + 모든 기사에서 일관된 UI(구독 가능/정보 없음).

  ① API 한도 여유(일 25,000회 중 1% 미만 사용) ② 신선도 체감 차이 작음 ③ 처리 비용(LLM 요약)
  ④ Redis 5분 캐시와 조화 ⑤ 정보 과부하 완화 ⑥ 업계 관행(15분~1시간).
- **핵심 메시지**: "더 자주 못 해서가 아니라 더 자주 할 필요가 없어서" 1시간. 설정으로 조정 가능.
- **관련 파일**: `docs/CRAWL_INTERVAL_RATIONALE.md`
